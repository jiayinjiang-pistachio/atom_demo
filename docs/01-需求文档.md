## 1. 产品定位

### 1.1 一句话定义

用户用一句自然语言描述需求，Agent 在隔离环境中逐个写入文件并实时展示过程，最终生成一个可直接运行、可交互、可下载的多文件 Web 应用。

### 1.2 解决的问题

传统「AI 生成网页」产品常见三类问题：

1. **结果是黑盒**：用户只看到最终页面，不知道模型做了什么、生成了哪些文件。
2. **半成品不可用**：生成结果只有静态外观，缺少真实交互与状态。
3. **无法继续迭代**：一次性输出，后续修改只能整页重来，也没有可回溯的历史。

Pistachio Atom 用「Agent 工具调用 + 文件系统 + 版本快照」把生成过程变成可观察、可迭代、可回滚的工程化流程。

### 1.3 产品原则

- **过程真实**：计划、工具调用、文件变化、token 用量都来自真实事件，不做假进度条。
- **结果可运行**：生成的应用必须有真实交互、演示数据与本地状态持久化。
- **不执行不可信代码**：生成代码只在独立预览域 iframe 中运行，服务端从不执行。
- **无注册可用**：匿名 guest token，打开即用，降低体验门槛。

## 2. 用户与典型场景

### 2.1 目标用户

| 用户类型 | 特征 | 核心诉求 |
|---|---|---|
| 匿名体验者 | 打开链接即试用，无账号 | 快速看到「一句话变应用」的效果 |
| 产品 / 设计评审者 | 需要判断生成质量与交互完整度 | 观察生成过程、验证交互、导出代码检查 |
| 轻量内容创作者 | 需要落地页、看板、打卡、作品集等小应用 | 低门槛获得可运行页面并分享 |
| 技术评估者 | 关注架构、安全、工程质量 | 查看 API、隔离策略、版本与错误处理 |

### 2.2 典型场景

1. **首次创建**：输入如「做一个支持拖拽的团队任务看板」，Agent 展示计划、逐个写文件，右侧预览自动出现可拖拽看板，并记住筛选条件。
2. **对话迭代**：「把整体改成深色，按钮改成圆角」，Agent 读取现有文件后增量修改，生成新版本，预览刷新。
3. **过程观察**：用户能看到 `update_plan`、`write_file` 等工具事件和文件内容变化，而不是只等一个结果。
4. **版本回滚**：对某次修改不满意，查看版本 diff，回滚为新版本，历史版本仍保留。
5. **导出交付**：下载指定版本的 ZIP，本地打开即可运行。
6. **只读分享**：生成分享链接，选择 7 天 / 30 天 / 永久；访客无需身份即可打开完整应用或带品牌外壳的分享页。
7. **提示词优化**：输入过于简短时，主动点击「优化」，模型结合项目上下文改写为更明确的需求，用户编辑确认后回填再发送。

## 3. 用户旅程

```
打开首页
  └─ 自动获取 guest token
      └─ 输入应用描述（可选填标题）
          └─ 创建项目（标题由后端生成，失败则用模板标题）
              └─ 进入工作区
                  ├─ 发送需求 → 意图识别
                  │    ├─ build：创建 run → SSE 实时展示计划/工具/文件
                  │    │         → 校验入口 → 生成不可变版本 → preview.ready
                  │    └─ chat：只保存消息并流式回复，不触发生成
                  ├─ 预览 iframe（独立 preview 域，sandbox）
                  ├─ 文件列表 / 只读文件内容
                  ├─ 版本列表 / diff / 回滚 / 导出
                  └─ 分享：创建链接 → 复制标准分享页或纯净应用页
```

## 4. 功能需求

优先级定义：**P0** 核心闭环必须可用；**P1** 重要增强；**P2** 加分项。

### 4.1 身份与访问

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-A1 | 匿名 guest 自动建立 | P0 | 首次访问自动调用 bootstrap，token 存 localStorage；刷新后身份保持 |
| FR-A2 | Bearer 鉴权 | P0 | 所有项目接口携带 `Authorization: Bearer`；缺失/无效返回 401；服务端只存 token 的 SHA-256 |
| FR-A3 | 数据归属隔离 | P0 | 非 owner 访问项目返回 404，不泄露项目是否存在 |
| FR-A4 | token 失效自愈 | P1 | 401 时前端清除旧 token 并重新 bootstrap 后重试一次 |
| FR-A5 | 账号体系 | 不在范围 | 注册/登录/OAuth 明确不做 |

### 4.2 项目管理

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-P1 | 创建项目 | P0 | 描述必填（≤4000 字），标题可选；成功返回项目并可直接进入工作区 |
| FR-P2 | 标题自动生成 | P0 | 未传标题时由 LLM 生成 6–20 字标题；演示模式/失败/超时 8s 回退模板分类标题 |
| FR-P3 | 项目列表 | P0 | 仅返回当前 guest 项目，按更新时间倒序，含标题、版本、更新时间 |
| FR-P4 | 删除项目 | P0 | 二次确认后删除，列表即时更新；不可恢复 |
| FR-P5 | 项目详情 | P0 | 返回标题、原始描述、入口文件、当前版本、文件清单、最近 run、消息历史 |
| FR-P6 | 重命名 | P1 | 后端 PATCH 与前端 store 已具备；**当前 UI 未提供入口**（见 8.2 缺口） |
| FR-P7 | 列表分页 / 搜索 | P2 | 后端默认 `limit=50`（最大 100），前端无分页、加载更多或搜索；超过 50 个的项目不会展示 |

### 4.3 对话与意图识别

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-C1 | 统一输入入口 | P0 | 同一输入框既可用于生成，也可普通聊天 |
| FR-C2 | 意图识别 | P0 | 规则优先：明确创建/修改 → build；明确寒暄/无关 → chat；模糊输入再走 LLM；演示模式或分类失败默认 build |
| FR-C3 | 聊天流式回复 | P0 | chat 意图通过 SSE 返回 `assistant.delta` 与 `chat.done`；界面显示真实「回复中」 |
| FR-C4 | 聊天不污染生成 | P0 | chat 消息 `run_id` 为空；Agent 上下文只读取 `run_id` 非空消息 |
| FR-C5 | 生成中禁止并发输入 | P0 | run active 或回复中禁用发送；单项目同时只允许一个活跃 run |
| FR-C6 | 取消生成 | P0 | 运行中可取消；取消后不生成版本，状态置为 cancelled |
| FR-C7 | Markdown 渲染 | P2 | 当前消息以纯文本 `whitespace-pre-wrap` 展示；规范中的 markdown-it + DOMPurify 未接入 |

### 4.4 Agent 生成

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-G1 | 多文件生成 | P0 | 必须产出 `index.html`，可附带 CSS/JS/JSON/SVG/MD/TXT 文件；使用相对路径引用 |
| FR-G2 | 工具化写入 | P0 | 仅能通过 `update_plan` / `list_files` / `read_file` / `write_file` / `delete_file` / `finish` 操作 VFS |
| FR-G3 | 路径与类型校验 | P0 | 拒绝绝对路径、`..`、非法字符与非白名单扩展名；路径长度受限 |
| FR-G4 | 大小限制 | P0 | 单文件 ≤ 32KB，单工程 ≤ 256KB；超限拒绝并返回明确错误 |
| FR-G5 | 无外部依赖 | P0 | 提示词要求不使用 CDN、外链字体/图片/API；生成内容自包含 |
| FR-G6 | 真实可交互 | P0 | 提示词要求响应式、可访问、带演示数据、真实交互；localStorage 需 try/catch 降级 |
| FR-G7 | 生成预算与收敛 | P0 | 最多 24 个工具步；单次输出长度受限；截断时最多 2 次拆分重试；重复覆盖/停滞时追加收敛提示并最终保留可用文件 |
| FR-G8 | 入口强校验 | P0 | `index.html` 缺失或为空时拒绝 `finish`，并追加提示继续生成；自动收敛同样不允许缺少入口 |
| FR-G9 | 迭代读取现状 | P0 | 迭代已有项目先 `list_files` / `read_file`，保留已有功能，不无故删除文件 |
| FR-G11 | 运行观测 | P0 | 事件流包含计划、工具、文件更新、token 用量、耗时；最终生成版本 |
| FR-G12 | 墙上时间超时 | P1 | 当前无单 run 墙上时间上限（仅有步数与 token 预算），长尾请求可能长时间占用并发槽 |

### 4.5 预览

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-V1 | 隔离预览 | P0 | 仅在 `preview.` 域 iframe 中加载，sandbox 固定为 `allow-scripts allow-same-origin allow-forms allow-modals` |
| FR-V2 | 版本化 URL | P0 | `/preview/{projectId}/{version}/index.html`；新版本切换 key 触发刷新 |
| FR-V3 | 预览域约束 | P0 | 校验 Host；仅暴露 `/preview/*` 与 `/share-preview/*`；CSP `connect-src 'none'`、`frame-ancestors` 指向主站 |
| FR-V4 | 加载态与失败处理 | P0 | 加载显示遮罩；失败保留上一可用版本，不显示白屏 |
| FR-V5 | 预览域直连 API | 禁止 | 预览域不能调用业务 API；生成应用无后端能力 |

### 4.6 版本管理

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-H1 | 版本列表 | P0 | 倒序返回版本号、来源、标签、文件数、总字节、创建时间 |
| FR-H2 | 不可变快照 | P0 | 每次成功 run 生成 JSON manifest 快照，创建后不可修改 |
| FR-H3 | 版本 diff | P0 | 支持 `a=0` 空白基线；输出新增/删除/修改统计；超长 diff 截断到 6000 字符并标注 |
| FR-H4 | 回滚 | P0 | 回滚生成新版本（source=restore），历史版本不变 |
| FR-H5 | 版本保留 | P0 | 最多保留 20 个版本；裁剪时保留仍被有效分享引用的旧版本 |
| FR-H6 | 对比任意两版 | P1 | 前端按相邻版本对比（上一版→当前版），未提供任意两版选择器 |

### 4.7 导出

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-E1 | ZIP 导出 | P0 | 可导出指定版本，默认当前版本；文件名 `atom-{projectId}-v{n}.zip` |
| FR-E2 | 离线可运行 | P0 | 解压后直接打开 `index.html` 可运行；不含任何服务端依赖 |
| FR-E3 | 批量/部署导出 | P2 | 未提供一键部署到第三方托管 |

### 4.8 只读分享

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-S1 | 创建分享 | P0 | 固定当前版本；有效期 7 天 / 30 天 / 永久 |
| FR-S2 | 分享上限 | P0 | 每项目最多 10 个有效分享，超出返回 429 `share_limit` |
| FR-S3 | 分享列表 | P0 | 仅 owner 可见；展示 slug、版本、有效期、状态 |
| FR-S4 | 撤销分享 | P0 | 删除幂等；撤销后公开接口立即 404 |
| FR-S5 | 公开元数据 | P0 | 无需鉴权；无效/撤销/过期统一 404，不区分原因 |
| FR-S6 | 两种打开形式 | P0 | `/s/{slug}` 带品牌外壳；`/s/{slug}/app` 纯净全屏应用 |
| FR-S7 | 分享预览缓存 | P0 | `/share-preview/{slug}/*` 响应 `Cache-Control: no-store`，撤销/过期立即失效 |
| FR-S8 | 访问统计 | P2 | 未实现分享访问计数或分析 |

### 4.9 提示词优化

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-O1 | 主动触发 | P0 | 输入框旁常驻「优化」按钮；只有用户点击才调用模型，不自动上传草稿 |
| FR-O2 | 短输入提示 | P0 | 草稿非空且去除首尾空白后 ≤20 字时显示「描述较简短，可点击优化补充细节」 |
| FR-O3 | 上下文改写 | P0 | 结合标题、已有文件路径、最近 6 条对话，改写为明确结构/交互/风格需求；模型目标 ≤400 字，服务端硬上限 4000 字符 |
| FR-O4 | 结果确认 | P0 | 弹窗对比原文与可编辑优化文；「使用优化结果」只回填输入框，不自动发送 |
| FR-O5 | 演示模式 | P0 | 未配置 Key 返回 409 `optimize_unavailable`，文案「演示模式不支持优化，可直接发送原描述」，不生成假结果 |
| FR-O6 | 异常处理 | P0 | 上游失败 502 `llm_error`；空结果 502 `optimize_empty`；超长 502 `optimize_too_long` |
| FR-O7 | 防重复与迟到响应 | P0 | 优化中禁止重复点击；关闭弹窗后迟到响应被丢弃 |
| FR-O8 | 注入防护 | P0 | 草稿以 `<draft>` 定界，system 明确其为数据而非指令 |

## 5. 非功能需求

| ID | 维度 | 要求 | 当前实现 |
|---|---|---|---|
| NFR-1 | 安全 | 生成代码绝不在服务端执行 | 满足：无 eval/exec/子进程；仅静态读取与 iframe 预览 |
| NFR-2 | 安全 | 预览域隔离 | 满足：独立域 + sandbox + Host 校验 + CSP |
| NFR-3 | 安全 | 密钥与身份不泄露 | 满足：Key 只在服务端环境变量；guest 只存哈希；日志不记录 prompt/token |
| NFR-4 | 安全 | 限流与配额 | **部分满足**：AI 并发限制为全局 2；`MAX_RUNS_PER_GUEST_DAY=20` 配置存在但**未强制**；无 IP 限流 |
| NFR-5 | 可靠性 | run 可取消、事件可回放 | 满足：取消标志、事件单调 seq、断线续传 |
| NFR-6 | 可靠性 | 事件先落库再发送 | 满足：SSE 每次轮询提交后推送 |
| NFR-7 | 性能 | SSE 低延迟 | 满足：断线续传 + 轮询 0.25s + 关闭代理缓冲 |
| NFR-8 | 性能 | 列表查询有上限 | 部分：项目列表后端 `limit≤100`（默认 50）；消息列表无上限；前端无分页 |
| NFR-9 | 可维护性 | 分层与类型 | 满足：routes/services/agent/db 分层；TS strict；Python 全量类型注解 |
| NFR-10 | 可测试性 | 自动化测试 | 满足：后端 106 个、前端 48 个测试通过；无 E2E 与 CI 配置 |
| NFR-11 | 兼容性 | 现代浏览器 | 桌面 Chrome/Safari/Firefox；移动端布局可用但未做 Tab 适配 |
| NFR-12 | 数据一致性 | UTC 存储、ULID、Alembic | 满足 |

## 6. 范围边界

### 6.1 本阶段明确在做

- 匿名身份、项目 CRUD、对话与意图分流
- DeepSeek Agent 生成、VFS 工具、实时事件、隔离预览
- 版本列表 / diff / 回滚、ZIP 导出、只读分享
- 提示词优化、演示模式、部署与基础工程质量

### 6.2 明确不做（本期）

| 不做项 | 原因 |
|---|---|
| 注册 / 登录 / OAuth | MVP 用匿名身份降低门槛；账号体系会显著增加复杂度 |
| 团队协作 / 权限 | 与匿名单用户模型冲突 |
| 支付 / 计费 | 非核心闭环 |
| 在线代码编辑 | 已评估并推迟：需要编辑器、保存语义、并发冲突与版本策略，成本高且当前「对话修改」已覆盖主路径 |
| 生成应用一键部署 | 涉及第三方托管、凭证与安全责任，P2 |
| 分享访问分析 | 需额外埋点与存储，非核心 |
| Redis / 消息队列 / 对象存储 | 架构约束：MySQL 为唯一事实源，降低运维面 |
| WebSocket / 前端直连 LLM | 契约与安全约束明确禁止 |
| 服务端执行生成代码 / SSR | 安全红线 |

## 7. 验收标准与成功指标

### 7.1 完成定义（DoD）

单个功能视为完成需同时满足：

1. 可运行，主路径可用。
2. loading / error / empty / success 四态完整，错误可重试。
3. 契约变更同步 Pydantic Schema、TS 类型、测试与文档。
4. `ruff check`、`ruff format --check`、`mypy app`、`pytest`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build` 全部通过。
5. 文档更新；未实现项明确标注。

### 7.2 核心验收场景

| 场景 | 通过条件 |
|---|---|
| 一句话创建 | 创建后能得到可交互应用与自动加载的预览 |
| 真实交互 | 按生成应用的需求 |
| 过程可见 | 能看到计划、工具调用、文件写入事件 |
| 迭代修改 | 第二次需求触发增量修改并生成新版本 |
| 回滚 | 回滚后预览回到目标版本，历史版本仍可查看 |
| 导出 | ZIP 解压后本地直接打开可用 |
| 分享 | 匿名访客可打开；撤销/过期立即 404 |
| 失败可恢复 | 生成失败有明确错误与重试入口 |

### 7.3 工程质量指标（当前）

## 9. 风险与假设

| 风险 | 影响 | 应对 |

| 模型输出不可控 | 生成失败、截断、循环 | 步数预算、截断重试、停滞收敛、入口校验；失败保留可用文件 |

| 版本膨胀 | 存储增长 | 20 版上限 + 分享引用保护 |
| 长尾 run 占用 | 其他用户排队 | 需补墙上时间上限与取消检查 |
| MySQL 单点 | 可用性 | 当前定位轻量 MVP；备份与连接池已配置 |

## 10. 后续扩展与优先级

优先级依据：**先降低滥用与稳定性风险，再补核心体验缺口，最后做增长型能力**。

### P0（继续投入首先做）

1. **配额与限流落地**：实现每日 guest 生成配额、按 IP/guest 限流；配置已存在，落地成本低、风险收益高。
2. **运行可观测性**：run 成功率、耗时、token、失败原因聚合；为容量与成本决策提供依据。
3. **墙上时间超时**：为每个 run 设置总时长上限并定期检查取消标志，避免占满并发槽。
4. **重命名入口**：后端与 store 已就绪，仅缺 UI，属于低成本补全。
5. **Markdown 安全渲染**：接入 markdown-it + DOMPurify，兑现规范并提升可读性。

### P1（体验与差异化）

1. **在线代码编辑**：CodeMirror 6 + 显式保存 → 生成新版本；需设计冲突与版本语义。
2. **移动端 Tab 布局**：对话 / 预览 / 文件三 Tab，适配小屏。
3. **模板与配方库**：常见应用类型（看板、打卡、作品集、落地页）沉淀为可选起点，降低模型波动。
4. **生成质量评估集**：固定 prompt 集合回归生成成功率与关键交互，作为模型/提示词改动的门禁。
5. **项目列表分页与搜索**。

### P2（增长与平台化）

1. 分享访问统计与只读二维码。
2. 生成应用的一键部署 / 自定义域名。
3. 多语言与主题定制。
4. 协作与账号体系（会改变匿名模型，需重新评估架构）。
